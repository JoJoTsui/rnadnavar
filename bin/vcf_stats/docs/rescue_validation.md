# Rescue VCF Validation Methodology

## What is a "rescued" variant?

A variant is **rescued** when it was called by one modality (DNA or RNA) but not
the other. The rescue workflow in the Nextflow pipeline (`rescue_workflow.nf`)
cross-references DNA and RNA calls at shared genomic positions. If a position
has evidence in only one modality, it is flagged as a rescue candidate.

The **rescue VCF** (generated by `run_rescue_vcf.py`) contains:
- Cross-modality annotations per position
- Per-caller VAF, DP, and FILTER values
- Consensus call information

## How is mismatch calculated?

The `rescue_validation.py` module computes per-sample per-caller validation
metrics by comparing BAM pileup data against caller-reported VCF fields:

### DP Comparison
For each caller (Mutect2, DeepSomatic, Strelka):
- **BAM DP** = BAM pileup total depth at the variant position
- **Caller DP** = `FORMAT/DP` field from the caller's VCF
- Mismatch = absolute difference between BAM DP and Caller DP
- Metrics: Pearson correlation (`dp_corr`), mean absolute deviation (`dp_mad`),
  mismatch percentage (`dp_mismatch_pct` — DP difference > 50%)

### VAF Comparison (Mutect2 + DeepSomatic only)
- **BAM VAF** = BAM ALT_DP / BAM DP
- **Caller VAF** = caller's VAF field (FORMAT/VAF or computed from AD)
- Metrics: Pearson correlation (`vaf_corr`), mean absolute deviation (`vaf_mad`)

### Strand Bias Comparison (Mutect2 only)
- Checks if BAM strand columns (F1R2_alt, F2R1_alt) exist
- Flags `has_sb_bam=True` if strand data is available

## Output files

| File | Contents |
|------|---------|
| `rescue_validation_report.tsv` | Per-sample per-metric validation results |
| `rescue_validation_summary.tsv` | Aggregated metrics across all samples |
| `bam_validation.tsv` | Per-sample BAM vs caller cross-validation |
