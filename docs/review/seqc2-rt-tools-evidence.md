## Interpretation of tool choices

The RNA branch asks DNA-oriented somatic models to evaluate spliced RNA tumor evidence versus DNA normal. DeepSomatic's [version 1.9 documentation](https://github.com/google/deepsomatic/blob/r1.9/README.md) lists WES/WGS and other DNA technologies, with no RNA model in its supported model list. Its WES execution here is confirmed; treating that model's RT confidence as calibrated evidence equivalent to DNA is an unvalidated assumption. This does not prove every RNA prediction is wrong or justify discarding RT entirely.

The [Strelka user guide](https://github.com/Illumina/strelka/blob/v2.9.x/docs/userGuide/README.md) documents RNA configuration for its germline workflow and DNA whole-genome/exome somatic workflows. Do not propose blindly adding `--rna` to the somatic command: establish supported options and benchmark behavior. The [official Strelka README](https://github.com/Illumina/strelka) recommends Manta indel candidates for best somatic indel performance. Their absence is a credible indel sensitivity limitation of this caller, not evidence that re-enabling Manta necessarily improves ensemble precision.

All three RT callers share the STAR/SplitNCigarReads/BQSR input, the same normal, and target intervals. Agreement between them is not three independent observations; all can inherit alignment artifacts or RNA/DNA biological discordance. Uniform caller-count thresholds cannot by themselves account for this correlation. Separately measure RT-only FP, DNA-supported RT gains, low-expression callable recall, splice proximity, homopolymers, allele fractions, editing transitions and caller scores.

STAR's permissive mapping options and Mutect2's exclusion of soft-clipped bases may trade sensitivity against alignment artifacts, especially at splice/indel boundaries. These are hypotheses requiring matched-input, one-option-at-a-time experiments. The existing evidence does not identify an optimal replacement threshold. Upgrading versions as a bundle would obscure attribution; retain exact environments and model artifacts during parameter ablation.

## Current second-pass design constraints (source, not executed results)

1. Candidate scope is **all RNA consensus records**, not just Somatic and not DNA-only candidates: `workflows/rnadnavar.nf:244` selects `BAM_PROCESSING.out.vcf` with status 2. It therefore includes rejected/NoConsensus RNA records if present in that VCF, but cannot systematically discover DNA-only locations never represented by first-pass RNA. This bounds opportunity; it is not a guarantee that the final allele set is an exact subset because recall and normalization can change nearby representation.
2. `modules/local/vcf2bed/main.nf:25` creates precisely `[POS-1, POS+len(REF)-1)` with no padding and no FILTER restriction. `subworkflows/local/prepare_intervals/main.nf:138` concatenates candidate BED files through collectFile; there is no explicit bedtools slop/coordinate merge step. Candidate windows, extraction windows and scoring windows need separate definitions. A broad recall claim cannot be supported by this candidate-only design.
3. Read IDs come from `samtools view -L BED | cut -f1` (`modules/local/extract_reads_id/main.nf:26`); Picard then selects those names from the original supplied alignment (`prepare_realignment_vcf/main.nf:141`). This can retain mates present elsewhere in the supplied BAM/CRAM; it is inaccurate to claim a simple region-only read slice necessarily drops every outside mate.
4. The supplied alignment is `BAM_PROCESSING.out.cram_variant_calling` (`workflows/rnadnavar.nf:253`), meaning RNA has already passed SplitNCigarReads and BQSR. FASTQ recovery from this file does not restore bases that were hard-clipped or records/mates already absent. [Samtools fastq documentation](https://www.htslib.org/doc/samtools-fasta.html) explains hard-clipped sequence is unavailable and one sequence per read-name/category is selected. Compare recovered pair counts, lengths, identities and quality distributions against source FASTQ before treating this as an independent full-read remapping.
5. FASTQ conversion writes singleton/other reads separately (`modules/nf-core/samtools/collatefastq/main.nf:18`, :32, :47). Its caller forwards only paired `out.fastq` into CAT_FASTQ (`subworkflows/local/bam_convert_samtools/main.nf:53`); singleton/other evidence is not realigned in this route. Mate loss upstream is therefore relevant even though name-based selection can retain intact mates.
6. Declared HISAT2 is **2.2.1** with samtools **1.20**, not an observed successfully executed version (`modules/nf-core/hisat2/align/environment.yml:7`). The extraction module separately pins samtools **1.15.1**. The paired HISAT2 source uses `--no-mixed --no-discordant`, known splice sites, optional strandness, and drops unmapped/mate-unmapped/secondary records via samtools (`modules/nf-core/hisat2/align/main.nf:62`). RNA ext.args are `--met-stderr --new-summary` (`conf/modules/alignment/bam_align.config:139`). This can improve specificity while reducing support from discordant/singleton reads; measure both, especially at rearrangements and splice boundaries.
7. Second-pass GATK preprocessing/calling works on the selected remapped RNA subset and first-pass DNA normal (`subworkflows/local/rna_realignment/main.nf:49`, :65). Coverage, local assembly context, duplicate handling and BQSR input distribution can differ from whole-library processing. Read-selection bias can alter both reference and alt support; extra caller votes from these outputs are not independent validation.
8. Second rescue combines first-round DNA with second-pass RNA individual VCFs and consensus (`subworkflows/local/second_rescue/main.nf:59`), then annotation/filtering and VEP. It does not require a first/second-pass agreement intersection in this module. Replacing RT evidence can both fix and introduce labels; audit a first-pass versus second-pass transition table, including disappearing sites and changes in support/VAF/rationale.

## Minimal discriminating experiments

Freeze baseline VCFs, versions, input manifests and truth scope. Score raw rescue, post-COSMIC/gnomAD, and post-filter output separately. Evaluate REDIportal annotation alone on the baseline, then RT-admission policies holding DNA constant. For realignment, first resolve tuple cardinality and validate candidate/read extraction on a bounded sample; compare source FASTQ extraction versus recovery from processed CRAM, and record paired/singleton counts and read-length distributions. Only after successful second-pass output should candidate-window expansion, HISAT2 pairing restrictions and caller thresholds be assessed. Report precision/recall for DNA-callable and RNA-callable strata, with counts of added true/false positives and lost DNA true positives. No result in the currently failed realignment run demonstrates a precision or recall gain.
